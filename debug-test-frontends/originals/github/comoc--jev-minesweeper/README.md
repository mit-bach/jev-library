# Jev × マインスイーパー

TypeSafe の System One モデル「Jev」に、ブラウザ上のマインスイーパーを解かせるデモです。

1手ごとに、数字に接した未開封マスそれぞれについて「このマスは地雷か？」という Noul 質問を作り、全問を1回のリクエストにまとめて Jev に送ります（TypeSafe の Speculative fan-out パターン）。Jev は各質問を独立に並列で評価し、地雷である確率を返します。どのマスを開くか、どこに旗を立てるかは、その確率を見てコードが決めます。

見えている情報だけから地雷の確率を正確に求める厳密ソルバーも同梱しています。ソルバーの役目は2つで、Jev が確信できないときの回送先と、Jev の確率の答え合わせです。

## 必要なもの

Node.js 20 以上と、TypeSafe の API キーです。依存パッケージはないので `npm install` は要りません。キーの発行は TypeSafe の [Quick start](https://docs.typesafe.ai/introduction/quickstart) を参照してください。キーがなくても、ソルバーと手動プレイは動きます。

## 起動

`.env.example` を `.env` にコピーし、`TYPESAFE_API_KEY=` の後ろにキーを書いてから起動します。

```sh
cp .env.example .env        # PowerShell では Copy-Item .env.example .env
npm start
```

表示された http://127.0.0.1:8787 をブラウザで開きます。画面右上の丸が緑なら、Jev を呼べる状態です。

`npm run mock` で起動すると、Jev の代わりに簡単な規則で答える偽の応答を使います。キーなしで画面の動きを確かめるためのもので、Jev の実力の目安にはなりません。画面にも「モックで動作中」と表示されます。

## 使い方

モードは4つあります。

「Jevだけ」は、Jev の確率だけで手を決めます。開く基準（既定 5%）以下のマスを開き、旗の基準（既定 95%）以上のマスに旗を立てます。開けるマスがないときは、旗を立てて聞き直すか、いちばん確率の低いマスを開きます（数字に接していない領域の平均の方が低ければ、そちらを開きます）。

「Jev＋ソルバー」は、基準を満たす答えが出た手だけを Jev に任せ、どのマスにも確信が持てないときは厳密ソルバーに回します（TypeSafe の Confidence-gated routing パターン）。

「ソルバーだけ」は比較用のベースラインで、API キーは要りません。

「自分で遊ぶ」では、クリックで開き、右クリックか F キーで旗を立てます。数字のマスをクリックすると、周りの旗が数字と同じ数のとき、残りの周りのマスをまとめて開きます。「Jevに聞く」を押すと、Jev の見立てを色で表示し、安全そうなマスを枠で示します。

「Jevへの渡し方」は、質問に載せる手がかりの形を切り替えます。「前処理あり」は「数字 − 周りの旗」をコードで計算し、`D4: exactly 1 of these 2 hidden cells is a mine: D5, E5` のような英文にして渡します。「生の数字だけ」は数字と周りのマスをそのまま渡し、算術も Jev に任せます。同じシードで両方を試すと、前処理の効き目を比べられます。セッション成績の表は、渡し方ごとに分けて集計します。

盤面のマスにカーソルを合わせると、「マスの詳細」に、そのマスについて Jev へ送った英文の手がかりと JSON、Jev の確率、厳密解を表示します。自動モードではクリックで表示を固定できます。盤面は矢印キーでも移動できます。

シードが同じなら盤面も同じです（自動モードの初手は常に中央）。URL の末尾（例：`#preset=beginner&seed=3&mode=jev&style=digested`）を共有すれば、同じ条件を再現できます。

## 評価の見方

「確率の当たり具合」は、Jev の確率を 10% 刻みにまとめ、実際に地雷だった割合と比べた較正グラフです。点が対角線に近いほど、Jev の確率どおりに地雷がありました。Brier スコアは 0 に近いほど良く、厳密解のスコアは、見えている情報から到達できる良さの目安です。「自信ありの誤り」は、開く基準以下と答えたのに地雷だったマスと、旗の基準以上と答えたのに安全だったマスの数です。

答え合わせに使う地雷の配置は評価専用で、手の決定には一切使いません。

## ベンチマーク

ブラウザなしで何局も打たせて、数字を取れます。同じ `--seed` なら同じ盤面の並びになるので、モードや渡し方を公平に比べられます。

```sh
npm run bench -- --mode jev,hybrid,solver --preset beginner --games 30
npm run bench -- --mode jev --style raw --games 30
```

勝率、平均手数、Jev が決めた手の割合、1局あたりの API 呼び出し数と費用、平均レイテンシ、Brier スコア、確実に安全なマスの検出率を表で出力します。基準は `--safe 0.05 --mine 0.95` で変えられます。

## テスト

```sh
npm test
```

ゲーム本体、厳密ソルバー（総当たりとの一致）、質問の組み立て、分割送信、どんな確率が返っても必ず終局することなどを確かめます。外部 API は呼びません。

## 構成

```
server.mjs              中継サーバ（画面の配信と、/api/jev から TypeSafe への中継）
lib/typesafe.mjs        System One API クライアント（429 や 529 は待って再試行）
lib/mock-jev.mjs        配線確認用の偽の応答（npm run mock）
bench.mjs               CLI ベンチマーク
public/index.html       画面
public/style.css
public/js/game.js       マインスイーパー本体（DOM に依存しない）
public/js/solver.js     厳密ソルバー
public/js/jev.js        盤面から Jev へのリクエストを組み立てる
public/js/agent.js      1手分の「考える」と「打つ」（画面とベンチで共用）
public/js/evaluate.js   較正と Brier スコア
public/js/app.js        画面の配線
test/run-tests.mjs      テスト
```

## 設計メモ

TypeSafe の API はブラウザからの直接呼び出し（CORS）を受け付けないため、ローカルの中継サーバを挟んでいます。API キーはサーバだけが持ち、ブラウザには渡りません。サーバは既定で 127.0.0.1 だけで待ち受けます。`HOST=0.0.0.0` にすると、同じネットワークの誰でもあなたのキーで Jev を呼べるようになるので注意してください。

Jev に渡す文面は英語です。Jev の主な学習言語が英語で、精度もいちばん高いためです。各質問には、そのマスの判断に必要な手がかりと近くの手がかりだけを載せます。質問は 80 問ずつに分けて並列に送り、1リクエストが Jev の上限（64k トークン）に収まるようにしています。

料金は入力 100 万トークンあたり $0.042 で、出力は無料です（jev-1.13、2026年9月時点の掲載価格）。画面の「このゲーム」に、そのゲームで使った入力トークンと費用の目安が出ます。
