01Concept

      

        
What a System One model is

        
A small model trained to do one thing: look at a state — the JSON-shaped facts your application already holds — and answer typed questions about it. Three question types cover almost every software decision.

      

    


    

      

        
noulYes / no

        
“Is this email a phishing attempt?”

        
Returns the probability of yes — a number you can threshold, average, or escalate on.

        

          
P(yes)0.87

          

        

      

      

        
choicePick one

        
“Which team should handle this?”

        
Returns the picked option, its confidence, and the probability of every option.

        

          
billing
79%

          
support
15%

          
sales
6%

        

      

      

        
scoreRate on a scale

        
“How severe is this incident?”

        
Returns a level on a scale you define — e.g. [low, medium, high, critical] — with confidence.

        

          
level3 / 5

          

        

      

    


    

      

        
Questions in one call share the state but can't see each other's answers.

        
Ask for a phishing verdict, a threat category and a severity in a single request — each is judged independently against the same evidence.

      

    


    
The contract was introduced by TypeSafe's hosted model Jev (api.typesafe.ai) and is implemented open-source by Kev — small local models (0.8B–27B) whose kev.serve exposes the same POST /v1/systemone API — and natively by Ollama 0.35+ with its nimble model. The playground above talks to Kev and Ollama straight from your browser; Jev's API currently only accepts calls from code.

  







  

    

      
02Comparison

      

        
System One vs. an LLM

        
An LLM generates plausible text. A System One model emits a typed judgment. Same transformer physics — a completely different product.

      

    


    

      

        
DimensionSystem One (Jev / Kev)General LLM

        
          
OutputTyped answers + probabilities: noul 0.87, choice "billing", score 3/5Free text you must parse, validate, and hope over

          
ContractExact response schema — your code reads fields, not regexesPrompt engineering + JSON mode + retries

          
UncertaintyFirst-class: every answer carries a probability you can thresholdHidden; wrong answers sound as fluent as right ones

          
Latency~0.2–1 s — pointer readout over prefill, no token-by-token decodeSeconds to minutes, scaling with answer length

          
CostTens of output tokens, flatHundreds to thousands, variable

          
Failure modeLow confidence → route to a human or a bigger modelA confident, fluent, wrong paragraph

          
TemperatureCalibrated by the training run — not a knob you babysitYou tune it away and hope

03Use cases

      

        
When to reach for it

        
If the output is a paragraph, you want an LLM. If the output is a decision, you want System One — often both: the LLM for talk, System One for the calls.

      

    

    

      

        
Use it for

        
    
          
  • RoutingWhich queue, team or model handles this request?
    • 
          
  • DetectionPhishing, fraud, abuse, prompt-injection flags
    • 
          
  • PolicyRefund eligible? SLA breached? Access allowed?
    • 
          
  • TriageSeverity score, dedup / match, priority ordering
    • 
          
  • Gates“Confident enough to auto-approve, or escalate?”
    • 
        

        
Anywhere your code says if (model_said_yes) after parsing prose — that's a System One call.

      

      

        
Not for

        
    
          
  • WritingAnything a human reads — emails, docs, summaries
    • 
          
  • ReasoningMulti-step logic, math, planning, debugging
    • 
          
  • GenerationCode, SQL, config, long answers
    • 
          
  • Open worldQuestions whose answer space you can't enumerate
    • 
        

      

    

  







  

    

      
04Contract

      

        
Anatomy of a query

        
One POST, two payloads. state is what your app knows; questions is what you need decided.

      

    


    

      

        
Request


POST /v1/systemone          # kev.serve :8009 · api.typesafe.ai/v1
Authorization: Bearer <key> # hosted Jev only; kev needs none

{
  "model": "kev-latest",
  "state": {
    "subject": "Your account has been locked",
    "body":    "Verify within 24h at secure-verify.example.com",
    "from":    "it-helpdesk@corp-itdesk.example.com"
  },
  "questions": {
    "is_phishing": {"type": "noul",
      "instructions": "Is this email a phishing attempt?"},
    "threat_type": {"type": "choice",
      "instructions": "What kind of threat is this?",
      "criteria": {"credential_harvesting": null,
        "malware": null, "spam": null, "benign": null}},
    "severity": {"type": "score",
      "instructions": "How dangerous is this email?",
      "criteria": ["harmless","annoying","risky","dangerous"]}
  }
}

      

      

        
Response


{
  "model": "kev-latest",
  "answers": {
    "is_phishing": {"type": "noul", "noul": 0.8705},
    "threat_type": {
      "type": "choice",
      "choice": "credential_harvesting",
      "confidence": 0.7937,
      "probabilities": {
        "credential_harvesting": 0.8453,
        "malware":   0.0018,
        "spam":      0.0135,
        "benign":    0.1394 }},
    "severity": {"type": "score", "score": 2.15,
                 "confidence": 0.61}   // continuous 0..n-1
  },
  "usage": {"input_tokens": 64, "output_tokens": 109},
  "latency_ms": 1116
}

      

    


    

      
state
JSON object of facts. Put what a human decider would need — subject, body, sender, order age — not your whole database row. It is the model's entire world for this call.

      
instructions
The question, phrased like a spec clause. “Is this email attempting to harvest credentials?” beats “phish?”

      
criteria
The answer space. Choice: {option: description|null} — describe an option when its name alone is ambiguous. Score: ordered list of level names. Noul: optional {true, false} descriptions to pin down what each verdict means.

      
model
kev-latest on a local kev.serve; jev-latest on TypeSafe's hosted API.

    

    
Companion endpoints on kev.serve: /v1/systemone/permute re-runs a choice question with shuffled option orders (detects position bias); /v1/systemone/separate runs each question in its own forward pass.

  







  

    

      
05Practice

      

        
Writing good questions

        
The model is only as precise as the question. Five rules, then three worked examples you can load straight into the playground.

      

    


    

      
    
        
  1. One axis per question
    “Is it phishing and urgent?” is two questions. Split them — each question is one decision.
    2. 
        
  2. Name your enums
    Option keys should be the strings your code switches on: credential_harvesting, not “stealing passwords”.
    3. 
        
  3. Spec, not vibes
    Instructions read like a reviewer checklist item, not a chat prompt.
    4. 
        
  4. Trim the state
    Irrelevant fields cost tokens and dilute attention. Include what a human judge would read.
    5. 
        
  5. Borderline is signal
    A noul ≈ 0.5 isn't a bug — it's the model saying “escalate me”. Threshold honestly.
    6. 
      

      

        

          Example A
          
Email triage

          
noul is_phishing · choice threat_type · score severity

          
Three independent judgments over one email — the exact shape a production anti-phishing pipeline uses.

          
        

        

          Example B
          
Refund routing

          
noul eligible · choice team · noul needs_human

          
A policy decision, a routing decision and an escalation flag — in one call.

          
        

        

          Example C
          
Review moderation

          
choice sentiment · noul recommend

          
Classification plus a buy / no-buy flag — the simplest possible call, and the default demo.

r = httpx.post(
    f"{BASE}/systemone",

const r = await fetch(`${BASE}/systemone`, {
  method: "POST",
  headers: {"content-type": "application/json"},
  body: JSON.stringify({
    model: "kev-latest",
    state: { text: "…" },
    questions: {
      angry: { type: "noul",
        instructions: "Is the customer angry?" },
    },
  }),
});
const { answers } = await r.json();
escalateIf(answers.angry.noul >= 0.7);

      

    


    

      

        
Can't connect from the browser?

        
Three gates sit between this page and a model. Reachability: Kev and Ollama listen on 127.0.0.1 by default — use --host 0.0.0.0 / OLLAMA_HOST=0.0.0.0:11434 to reach them from another device. The server must trust this site (CORS): Kev allows every origin; Ollama needs OLLAMA_ORIGINS="https://luongnv.com" (); TypeSafe's API currently allows no outside sites, so use Jev from code. Your browser must allow local access: on an HTTPS page like luongnv.com, Chrome and Edge 142+ ask once before calling localhost or a LAN IP — click Allow, or re-enable it under the site-info icon → Local network access.

        
Simplest fallback: serve this page locally (git clone → python3 -m http.server → http://localhost:8000) — localhost pages need no permission, and Ollama trusts them by default.
