# Draft Jev Evaluator

元情報から複数の解説原稿を生成し、Jevで評価して比較するローカル向けプロトタイプです。OpenRouterのモデルや生成プロンプト、Reasoning Effortを変えて、文章と評価を横並びで確認できます。

## 主な機能

- 生成プロンプトの追加・編集・有効／無効切り替えと、ブラウザへの自動保存
- OpenRouterのモデル検索、入力・出力料金表示、Reasoning Effortの指定
- 元情報と生成文をJevに渡した評価、総合点・各軸・NG判定の可視化
- 文章と評価の横並び比較、お気に入り、自動ベスト
- 実行履歴、追加生成、履歴のマージ、名前変更、候補削除
- 評価基準の編集と、生成・Jev評価のUSD費用記録

## 起動

Docker EngineとDocker Compose、OpenRouterのAPIキーが必要です。依存関係はコンテナ内でインストールするため、ホストへのPythonやNode.jsのインストールは不要です。

リポジトリを取得し、ルートディレクトリで初回のみ実行します。

```bash
cp .env.example .env
```

`.env`を開き、`API_KEY`を自分のOpenRouter APIキーに変更してください。その後、起動します。

```bash
docker compose up -d --build
```

同じPCなら `http://localhost:8097`、別のPCなら `http://サーバーのIPアドレス:8097` をブラウザで開きます。別PCからは同じネットワークへの接続と、ポートへのアクセス許可が必要です。

このアプリにはログイン機能がなく、画面からAPI呼び出しや保存データの操作ができます。信頼できるローカルネットワーク内で使ってください。ソースコードのGitHub公開と、稼働中のアプリをインターネットへ公開することは別です。

### 設定

| 環境変数 | 内容 | 初期値 |
|---|---|---|
| `API_KEY` | OpenRouterのAPIキー。ブラウザには渡しません | 要設定 |
| `OPENROUTER_API_KEY` | `API_KEY`未設定時の代替キー | 未設定 |
| `PORT` | ホスト側の公開ポート | `8097` |
| `GENERATION_MODEL` | 画面の初期選択モデル。実行ごとに変更可能 | `openai/gpt-6-luna-pro` |
| `EVALUATION_MODEL` | Jev評価に使うモデル | `typesafe/jev-1.13` |

モデル一覧はOpenRouterから取得し、10分間キャッシュします。モデルの提供状況と利用条件はOpenRouter側に依存します。

### 停止・更新

```bash
# 起動状況
docker compose ps

# ログ
docker compose logs --tail 100

# 停止（保存データは残ります）
docker compose down

# ソース変更後のビルドと起動
docker compose up -d --build
```

コンテナを再起動すると実行中の処理は中断として保存され、自動再実行はしません。更新は実行完了後に行ってください。

## 使い方

1. 元情報を貼り付け、生成プロンプトを入力します。
2. 使用するプロンプトを「有効」にし、モデル・Effort・生成数を指定します。
3. 生成ボタンをクリックします。Enterでは生成を開始しません。
4. 結果のチェックボックスで候補を選び、「文章を比較」「評価を比較」で確認します。

生成数の初期値は1です。**有効なプロンプト数 × 生成数**を生成します。例えば3種類のうち2種類が有効で、生成数が2なら合計4件です。プロンプトは最大10種類、各プロンプトの生成数は最大20件です。生成は最大10並列、Jev評価は最大3並列で進みます。

プロンプトの本文と有効状態はブラウザのlocalStorageへ自動保存します。同じブラウザ・同じ接続先で復元されます。履歴を開くと当時の条件を表示し、「ブラウザ保存済みのプロンプトに戻す」で下書きへ戻せます。各候補にも実際に使用したプロンプトを記録します。

### モデルとReasoning Effort

候補一覧の料金は100万トークン当たりUSDです。長文・追加機能などによる追加料金は含みません。

Effortはモデルが公開する対応値から選びます。初期選択は対応する場合`medium`。「未指定」を選ぶとモデル側の既定に従います。指定したEffortに対応する接続先を使い、非対応の指定を別の値へ自動変更しません。

各結果の「生成条件」で、指定値・送信パラメーター・応答モデル・プロバイダー・usageを確認できます。APIが実際の適用Effortや推論トークン数を返さない場合は確認不可・未取得と表示します。同じEffort名がモデル間で同じ計算量を保証するものではありません。

### 評価・お気に入り・ベスト

元情報と生成文を照合して評価します。元情報そのものの真偽や、外部の事実確認は行いません。

| 評価軸 | 総合点の重み |
|---|---:|
| 具体性 | 25% |
| 裏付け | 20% |
| 確定度 | 20% |
| 重要性 | 15% |
| 構成 | 10% |
| 明瞭さ | 10% |

各軸は0〜3点で、総合点は100点満点・小数1桁に換算します。重大な問題の確率（`suspicious`）が0.3以上ならNGです。

- **お気に入り**：手動で付ける★です。
- **ベスト**：同じ一覧のOK候補のうち、総合点が最高のものです。同点は全件に表示し、処理中は暫定ベストとします。

「評価基準を編集」で指示文と採点基準を保存できます。変更は次の新規生成から適用し、過去の結果への追加生成では当時の基準を使います。重みとNG閾値は固定です。

### 履歴とマージ

履歴は画面最下部から開けます。実行名はその行で編集して保存できます。

- **追加生成**：元情報・プロンプト・有効状態・評価基準を固定し、モデル・Effort・生成数を変えて候補を追加します。
- **マージ**：選択した履歴を新しい履歴へまとめます。元情報・評価基準・記録済み評価モデルが一致しなければ、理由を表示して拒否します。プロンプト・有効状態・生成モデル・Effortの違いは許容します。
- マージ元は残し、使用プロンプトを統合してP番号を振り直します。同じ元候補は重複させず、お気に入りと生成条件も保持します。統合後のプロンプト上限は10種類です。
- 候補を削除しても残った候補の番号は変わらず、削除済み番号は再利用しません。実行中の履歴はマージ・削除できません。

### 費用

OpenRouterから報告される費用をUSDとして記録し、生成・Jev評価・合計を表示します。候補削除後も発生済み料金は台帳に残ります。取得できない料金は0とせず不明とし、確認済み額を表示します。

マージ自体はAPIを呼びません。マージ履歴の費用は元実行の費用を含むため、元履歴とマージ履歴の金額を単純合計すると重複します。

## データの保存先

| 保存先 | 内容 |
|---|---|
| `.env` | APIキー・起動設定 |
| `data/runs.sqlite3` | 元情報、実行条件、原稿、評価、履歴、お気に入り、費用、編集した評価基準 |
| ブラウザのlocalStorage | プロンプトの下書き・有効状態 |

`.env`と`data/`はGitとDockerビルドの対象から除外しています。入力した元情報・生成プロンプト・生成文は、生成・評価のためOpenRouterへ送信されます。

DBをバックアップする場合は、処理完了後にコンテナを停止してから`data/`をコピーしてください。コンテナを再作成してもデータは残りますが、`data/`の削除では失われます。
